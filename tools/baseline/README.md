# 블라인드 베이스라인 채점

캡션 품질이 나아지고 있는지를 **사람이 블라인드로 채점해서** 재는 도구.

## 왜 필요한가

- `caption_score`는 AI가 자기 글에 매기는 점수라 개선 판단 근거가 못 된다.
- 인스타 실참여도 당분간 못 쓴다 (2026-08 실측: 운영 계정 팔로워 1명,
  게시물 200개에 좋아요 총합 6 → 분산 0).
- 그래서 당분간 사람 블라인드 채점이 유일한 측정 수단이다.

## 설계

같은 시나리오에 대해 RAG 조건만 바꿔 생성하는 **짝지어 비교**.
시나리오 난이도가 교란 요인이 되지 않는다.

| 조건 | 내용 |
|---|---|
| `ai_rag` | RAG에 AI 생성분이 쌓인 상태 (현재 프로덕션이 도달한 상태) |
| `human_rag` | 사장님이 직접 쓴 캡션이 RAG에 있는 상태 |
| `cold` | RAG 없음 |
| `anchor` | 실제 사람이 쓴 캡션 (절대 기준선, 생성 아님) |

8시나리오 × 3조건 + 앵커 3개 = **27문항**.

> **anchor는 완전한 블라인드가 아니다.** 실제 계정 게시물은 고정 정보블록 구조라
> 형식만으로 구분된다. 인트로만 떼어 길이를 맞췄지만 티가 날 수 있다.
> 핵심 비교(`ai_rag` vs `human_rag` vs `cold`)는 형식이 같아 블라인드가 유지되므로
> 주 결론에는 영향이 없다. anchor는 "사람 글은 몇 점대인가"의 참조점으로만 읽을 것.

## 채점 항목

1~5점 4개 + 결함 개수 + 종합 판정. **가중 합산하지 않는다** —
항목별로 봐야 어디가 문제인지 보인다. 총점 하나로 뭉치면 `caption_score`의 문제를 반복한다.

| 항목 | 묻는 것 |
|---|---|
| `ai_feel` | 사람이 쓴 글 같은가 |
| `shop_fit` | 이 샵이 쓸 법한 글인가 (개인화) |
| `specific` | 구체적인가, 아무 샵에나 붙는 일반론인가 |
| `hook` | 첫 문장이 스크롤을 멈추게 하는가 |
| `defects` | 문장 파손·중복·사실 오류 개수 |
| `verdict` | **그대로 올리겠는가 / 조금 고쳐서 / 안 올림** ← 헤드라인 지표 |

## 사용법

```bash
# 1) 채점 대상 생성 (LLM 호출 24회 + RAG 압축 2회)
python tools/baseline/generate_items.py
#    → out/items.json (채점지용, 라벨 없음)
#    → out/key.json   (정답표 — 채점자에게 주지 말 것)

#    생성 중 LLM 파싱 실패로 fallback 캡션이 섞이면 해당 문항만 재생성:
python tools/baseline/generate_items.py --repair

# 2) 채점지 만들기
python tools/baseline/build_sheet.py
#    → out/채점지.html

# 3) 채점자에게 채점지.html 하나만 전달
#    (브라우저로 열면 됨. 서버·인터넷 불필요. 중간에 닫아도 이어서 가능)
#    다 하면 "평가결과_이름.json"이 저장된다 → 받아서 out/results/ 에 넣는다

# 4) 집계
python tools/baseline/aggregate.py
```

## 채점자

혼자 채점하면 표본이 1이고, 만든 사람이라 조건을 알아볼 위험이 있다. 3명 권장:
지현님 / 실제 바버샵 사장님 / 마케팅 감각 있는 제3자.
사장님 한 분이 나머지 둘보다 가치가 크다.

## 주의

- `out/key.json`을 채점자에게 주면 실험이 무효가 된다.
- 코드를 바꾼 뒤 다시 재려면 `generate_items.py`를 다시 돌려 새 문항을 만들고,
  같은 채점자에게 다시 채점받아야 비교가 된다.
