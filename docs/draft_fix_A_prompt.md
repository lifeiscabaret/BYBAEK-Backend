> 상태: **초안(미적용).** 어머님(원장) 회신 2건(① 미용실 전용 시술 목록 ② g28 셰그컷) 도착 후 확정.
> 범위: `agents/photo_filter.py` 프롬프트/주석 문구만. **게이트 로직·스키마 변경 없음(그건 PART 2).**

## 이 수정이 고치는 실제 프로덕션 오류
현재 프롬프트/주석은 "롱헤어 = 미용실 스타일 = 탈락"으로 읽힐 여지가 있다. 그러나 원장 자문 결과
멀릿컷·슬릭백·롱트림 등 **길이 있는 바버샵 시술**이 존재한다. 즉 현재 코드는 길이를 잘못된 탈락
근거로 쓰고 있고, 이는 데모샵 문제가 아니라 **어느 샵이든 긴 바버 시술 결과물을 올리면 오탈락**하는
구조적 오류다. 수정 A는 이 오류를 제거한다.

## 변경 1 — `_build_vision_prompt()` 핵심 원칙 블록 (photo_filter.py ~410)

### AS-IS
```
BYBAEK 필터링의 유일한 판단 기준은 "사진에 바버샵 스타일 기법(페이드/언더컷/

```

### TO-BE (초안)
```
BYBAEK 필터링의 유일한 판단 기준은 "사진에서 바버샵에서 하는 시술 형태가
식별되는가"이다. 통과 사유는 오직 '시술이 식별됨' 하나다.
- '홍보에 쓸 만해 보인다 / 분위기가 좋다 / 착장이 멋지다'는 통과 사유가 아니다.
  분위기·착장 사진이라도 시술이 안 보이면 탈락이다.
- 성별은 무관하다.
- 머리 길이는 판단 기준이 아니다. 멀릿컷·슬릭백·롱트림처럼 길이 있는 바버샵
  시술도 있다. '길어서 미용실'은 틀린 판단이다.
- 탈락 기준은 "바버샵에서만 하는 시술인가"가 아니라 "바버샵에서도 하는가"이다.
  미용실도 하는 시술이라는 것은 탈락 사유가 아니다. 탈락은 "미용실에서만 하고
  바버샵에서는 하지 않는 시술"로 한정된다.
- 사진의 출처(실제 손님/레퍼런스/스톡/연예인 캡처)는 판단 기준이 아니다.
- 매장 맥락(배경/유니폼/도구/이발 장면) 유무도 판단 기준이 아니다.

[바버샵 시술 예시 — 판단을 돕는 목록이지, "목록에 없으면 탈락"이 아니다]
· 시술명(예): 가일컷, 버스트페이드컷, 사이드파트, 크루컷, 포마드컷, 크롭컷,
  드랍컷, 아이비리그컷, 슬릭백, 슬릭백언더컷, 플랫탑, 롱트림, 리젠트컷,
  버즈컷, 페이드컷, 멀릿컷, 모히칸
· 페이드 옵션(예): 제로/로우/미들/하이/스킨 페이드, mm 단위 지정(1mm·3mm 등), 버스트 페이드
· 실제 시술은 [시술명 + 페이드옵션]의 조합이다 (예: "크루컷 + 스킨 미들페이드").
```

## 변경 5 — 손질 판별 축 명시 (원장 자문 5-3, 핵심 원칙 블록에 추가)

### 배경 (원장 자문 5-3)
- 옆뒤가 **짧은** 스타일 → 사진으로 손질(신선도) 여부 구분 가능.
- 옆뒤가 **긴** 스타일 → 사진으로는 손질 여부 판단 어려움 (전문가도).
- → 판단 축은 "식별 가능한 **시술 형태**의 유무"이며 "최근에 다듬었는가(신선도)"는 기준이 아니다.

### 핵심 원칙 블록에 추가할 문구 (초안)
```
[손질(신선도)은 판단 기준이 아니다]
- "다듬은 흔적", "손질한 지 얼마 안 됨" 같은 신선도는 판단 근거로 쓰지 않는다.
  (긴 스타일은 전문가도 사진으로 신선도 판별이 어렵다. 신선도를 기준으로 쓰면
   멀릿·슬릭백·롱트림 같은 긴 바버 시술이 구조적으로 전부 탈락한다 —
   "롱헤어=미용실" 오류와 같은 결과.)
- 긴 스타일은 형태로 판단한다: 실루엣, 위아래 길이 배분(예: 멀릿 = 윗머리 짧고
   뒷머리 김), 넘긴 형태(예: 슬릭백), 정돈된 라인 등.
- 단, 형태가 전혀 없는 긴 머리(스타일도 정돈된 라인도 없는 생머리)는 탈락.
  사유는 "길어서"가 아니라 "식별 가능한 시술 형태 없음".
```

> ⚠️ **주의(내가 초안에 심었던 함정)**: 변경 3의 최초 문구에 "다듬은 흔적"이 들어가 있었음.
> 이건 신선도 기준이라 긴 바버 시술을 전부 탈락시킴 → 5-3 반영해 제거·수정 완료.
> 앞으로도 프롬프트에 "다듬은/손질/신선" 류 표현이 재유입되지 않게 검토할 것.
